# FOM 赛车涂装与贴花可复用包 v54

## 1. 这个包包含什么

这是当前已确认的 FOM 赛车运行时涂装、贴花和动态尾灯系统。包内已经包含：

- 当前赛车模型 `f1_2026_fom-nyu-purple-color-only.glb`
- 左右车身、尾翼和车头贴花
- DeltaX、ZJUAP、创变者及 6 组赞助商素材
- 10 种可实时切换的车身主体颜色
- 8 种可实时切换的分区涂装
- 左右贴花镜像、三轴旋转、大小、移动、翻转、正反和曲面吸附 GUI
- 每秒闪烁 2 次的车尾红灯
- Three.js r165、GLTFLoader、DRACOLoader、DecalGeometry 和 Draco 解码器
- 当前已确认参数及历史记录

整个文件夹约 `6.4 MB`。两个约 60 MB 的旧第一视角 GLB 不属于当前系统的运行依赖，因此没有放入本包。

## 2. 最重要的接入说明

贴花 Logo **没有烘焙进 GLB**。单独把 GLB 导入主游戏，只会得到赛车模型和原始材质，不会自动出现当前贴花、分区涂装和动态尾灯。

要保持当前外观，需要同时接入：

1. `f1_2026_fom-nyu-purple-color-only.glb`
2. `src/fom-decal-preview.js` 中的贴花投射、分区 Shader、颜色切换和尾灯逻辑
3. 根目录、`assets/` 和 `抖音官方赞助商logo/` 中的贴图素材
4. `vendor/` 中的 Three.js 加载和 DecalGeometry 依赖，或者改成主游戏中同版本、同实例的 Three.js 依赖

如果主游戏已经使用 Three.js，请优先复用主游戏自己的 `THREE`、`GLTFLoader`、`DRACOLoader` 和 `DecalGeometry`，不要在同一页面加载两份 Three.js。

## 4. 独立运行预览

ES Module、GLB 和纹理不能可靠地通过 `file://` 直接打开。请在本文件夹启动 HTTP 服务：

```bash
cd "FOM赛车涂装贴花可复用包-v54"
python3 -m http.server 4173
```

然后打开：

```text
http://localhost:4173/fom-decal-preview.html
```

## 5. 坐标与模型基准

所有已保存贴花参数都是赛车根节点 `carRoot` 的局部坐标：

- `X`：左右，右侧为正，左侧为负
- `Y`：高度，向上为正
- `Z`：前后，车头方向为正，车尾方向为负
- 旋转顺序：`XYZ`
- 角度单位：GUI 和配置使用度；传入 Three.js `Euler` 前转换为弧度

当前代码加载模型后会先执行同样的基准化：

1. 计算整车包围盒。
2. 将包围盒中心的 `X`、`Z` 移到原点。
3. 将包围盒最低点移动到 `Y = 0`。
4. 更新世界矩阵后再生成贴花。

主游戏若跳过、改变这个平移步骤，或者改变模型根节点缩放，现有贴花坐标就会偏移。最安全的做法是保持模型内部几何和 `carRoot` 缩放不变，在更外层父节点上移动、旋转或缩放整台赛车。

## 6. 作用机制

### 6.1 曲面贴花

Logo 使用 Three.js `DecalGeometry` 运行时投射到赛车表面，不是悬浮平面。

- 侧面贴花从左右各自的外侧投射。
- 左右投射使用对应半轴的车身表面，避免穿过中间车体贴到另一侧。
- 车头贴花从上向下投射。
- 尾翼贴花使用车尾目标材质集合投射。
- SVG 会先在高分辨率 Canvas 中栅格化，减少放大后的模糊。
- 贴花材质使用 `depthWrite: false`、`polygonOffset` 和较高 `renderOrder`。
- 小法线安全间距用于防止 Z-fighting，但不会形成肉眼可见的隆起。

贴花需要在模型完成加载、根节点完成定位且 `matrixWorld` 已更新后创建。

### 6.2 主体颜色

颜色切换只处理以下三个车身主题材质：

```text
livery_audi_01
fom_car_dummy_decal
boya
```

只更新材质基础颜色，不替换原始贴图，不修改轮胎、轮毂、碳纤维、Logo 或尾灯材质。因此轮胎原始纹理和车身表面纹理会保留。

### 6.3 分区涂装

分区涂装不创建新的几何体。`installLiveryPartitionShader(material)` 使用 `material.onBeforeCompile`，根据原车身顶点局部坐标计算颜色遮罩，并在原材质同一表面混合辅助色。

这意味着：

- 分区不会隆起。
- 不会与车壳穿模。
- 不会额外覆盖赞助商 Logo。
- 原材质明暗和纹理细节仍会参与最终颜色。

Shader 使用 4 个运行时 uniform：

```text
uLiveryScheme      分区方案编号，0–7
uLiveryThemeColor  主体颜色
uLiveryAccentA     第一辅助色
uLiveryAccentB     第二辅助色
```

### 6.4 动态尾灯

系统只查找名称为 `rear_light` 的材质，并为其建立克隆，不修改其他白色部件。

- 周期：`500 ms`
- 红色阶段：`250 ms`
- 原色阶段：`250 ms`
- 频率：每秒 `2` 次
- 红色：`#ff1808`
- 红色阶段自发光强度：`4`

### 7.3 贴花 GUI 参数

每个贴花都支持：

- `scale`：整体大小
- `width`：宽度倍率
- `height`：高度倍率
- `x`、`y`、`z`：局部位置
- `rotationX`、`rotationY`、`rotationZ`：三轴旋转
- `flipHorizontal`：水平翻转纹理
- `flipVertical`：垂直翻转纹理
- `reverseFacing`：投射正反切换
- 曲面吸附
- 左右镜像同步

预览页面中选择贴花后，也可以通过脚本修改 GUI：

```js
document
  .querySelector('[data-decal-target="right"]')
  .click();

const scaleInput = document.querySelector("#decal-scale");
scaleInput.value = "1.2";
scaleInput.dispatchEvent(new Event("input", { bubbles: true }));
```

生产环境不需要 GUI 时，可以保留 `PRESETS`、`states`、`rebuildDecal()`、`createDecalMesh()` 和投射辅助函数，直接修改状态后调用：

```js
states.right.scale = 1.2;
states.right.y = 0.424;
states.right.z = -0.295;
rebuildDecal("right");
```

不要在每一帧重建贴花。只在参数发生变化、模型形变或贴花素材更换后重建。

### 左右镜像规则

从一侧自动同步到另一侧时：

```text
X          取相反数
rotationY  取相反数
rotationZ  取相反数
其他大小、位置、rotationX、翻转和正反参数复制
```

主 Logo、DeltaX 和全部左右赞助商都支持镜像。车头和尾翼贴花没有左右镜像对象。

## 9. 合并到现有 Three.js 主游戏

推荐按下面顺序接入：

1. 使用主游戏的 Loader 加载包内 GLB。
2. 保持模型内部缩放不变，并执行与本预览相同的根节点居中和落地步骤。
3. 遍历模型，按材质名收集车身主题材质、贴花投射表面和 `rear_light`。
4. 对主题材质安装 `installLiveryPartitionShader()`。
5. 加载全部贴花纹理。
6. 创建前部、后部和左右独立贴花。
7. 应用已保存的 `PRESETS`。
8. 在游戏更新循环中只更新尾灯相位；颜色或贴花参数变化时再更新对应对象。
9. 将整台车放进主游戏的外层父节点，通过父节点控制世界位置和缩放。

从 `src/fom-decal-preview.js` 抽取到主游戏时，场景、相机、灯光、地面、鼠标观察和 HTML GUI 都是预览专用，可以删除。需要保留的核心区域是：

- 资源和材质名称常量
- `LIVERY_SCHEMES`
- `PRESETS` 和 `states`
- 纹理高清化与透明裁切函数
- 投射表面准备和贴花几何构建函数
- `createDecalMesh()` 与 `rebuildDecal()`
- 曲面吸附和左右镜像函数
- `installLiveryPartitionShader()`
- `applyThemeColor()` 与 `applyLiveryScheme()`
- `rear_light` 材质注册和闪烁更新

## 10. 引擎适配注意事项

- 本包预览基于 Three.js `r165`。
- 如果主游戏 Three.js 版本不同，应使用该版本匹配的 Loader 和 DecalGeometry 做一次回归检查。
- 主游戏使用 React Three Fiber、Babylon.js、Unity 或 Unreal 时，不能直接复制这份 Three.js 代码；应复用参数、材质选择规则和作用机制，并用对应引擎重写投射和 Shader。
- 若替换 GLB，材质名、模型原点、尺寸或车壳拓扑改变后，贴花投射筛选和坐标需要重新校准。
- 若模型有骨骼或顶点动画，静态 DecalGeometry 不会自动跟随顶点变形，需要绑定、烘焙或改用动态投影材质。
- 浏览器运行必须通过 HTTP(S)，不要直接双击 HTML 使用 `file://`。

## 12. 完整性保护

合并时请保持以下原则：

- 不要全局替换白色材质，必须按明确材质名处理。
- 不要修改轮胎、轮毂和碳纤维材质。
- 不要把分区涂装重新做成悬浮平面。
- 左右侧贴花必须各自从外侧投射并限制对应半轴。
- Logo 的显示层应高于原车身分区。
- 改动模型坐标、缩放或材质名后，应重新检查全部贴花。
